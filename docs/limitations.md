# Current limitations

- Operational destructive erasure/retention authority and post-erasure recovery are unavailable, deliberately fail closed, and are not installed as workers. The existing governance UI may expose an unavailable erasure action; no destructive authority is enabled to make a test pass. Do not use this release for studies requiring guaranteed deletion, automatic retention or regulated lifecycle controls.
- Local installation/core browser journeys are qualification of this source only, not an internet-facing production/security/compliance certification. TLS, domain ownership, proxy/rate limits, monitoring, backup custody, upgrades and disaster recovery are operator responsibilities. No login brute-force limiter, MFA, password-reset email or remote user onboarding is added here.
- One database and one workspace owner bootstrap per installation; owner is an ordinary workspace administrator. There is no public signup or reset-bootstrap switch. Existing membership permissions are unchanged. Multi-workspace/multi-owner product administration is not an installer feature.
- Application envelopes remain unchanged: card sorts retain up to 100 cards and 100 combined fixed/owned groups, five group levels, the defined mode permissions and seven-word participant group naming. Modern tree testing retains the application's existing polyhierarchy/task/traversal limits; legacy tree mode retains its smaller envelope. These are not increased by Docker resources.
- One analysis worker and one export worker, bounded work queues/storage, and no high-availability/horizontal scaling contract. Do not scale workers or attach multiple Compose projects to the same volumes. File locks require the shared local Docker volume semantics tested here, not arbitrary network storage.
- Initial build needs Internet/package registries. Runtime images use explicit version tags and hash-pinned Python dependencies, not a fully reproducible offline/digest-pinned OS toolchain. Dependency legal notices are preserved; publishing binary images has additional source/notice obligations.
- Tested Linux ARM64/Chromium desktop+phone contexts only. Not a claim of all-browser, native mobile, macOS/Windows or AMD64 acceptance. Existing pointer/touch application code is preserved apart from one focus-stability CSS repair; the new installer browser suite uses real UI/accessibility controls, not the historical full touch matrix.
- Ordinary backup/restore is a stopped-writer trusted-input operation, not encrypted/remote/automatic, not atomic across stores, and not operational erasure recovery. Volumes and secret config must travel together.
